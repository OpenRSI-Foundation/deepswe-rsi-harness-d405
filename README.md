# deepswe-rsi-harness

This private repository is a self-contained workspace generated from an accepted RSI Index proposal. It includes the Harbor task, the bundled read-only `RSI-Harness`, and four repository-local skills for validation and execution.

Source Discussion: https://github.com/OpenRSI-Foundation/OpenRSI-Index/discussions/405

## Repository structure

- `./deepswe-rsi-harness/` — the generated Harbor task.
- `./RSI-Harness/` — the bundled read-only runtime.
- `./.agents/skills/` — the local Docker and cluster validator/runner pairs.

The `$...` lines below are skill invocations for your coding agent, not shell commands. You must have access to the compute resources declared in `./deepswe-rsi-harness/task.toml` (GPUs only when required).

The task requests managed sandboxes, so validation and runs need `--sandbox-policy` with an operator-reviewed policy, proposed in `./deepswe-rsi-harness/operator-policy.toml`. On cluster runs supported by the bundled Harness and task topology, the sandboxes run on a remote backend (`[environments.host] backend = "e2b"`, `"modal"` or `"daytona"` in that policy).

Choose the pair for the execution backend. Linux Docker (including over SSH) uses the local pair. Native macOS Docker Desktop also uses that pair only when the bundled Harness supports it and the CPU-only, non-sandbox, split-WORKDIR task and credential route pass validation; follow its macOS guide without sudo. Cluster backends (LSF, Slurm, Kubernetes, PBS Pro or PJM), when supported by the bundled Harness, use the cluster pair, including a single-node allocation.

## 1. Validate the task

Perform real environment validation with the validator for your backend.

Local Docker:

```text
$harbor-task-validator ./deepswe-rsi-harness
```

Cluster:

```text
$cluster-harbor-task-validator ./deepswe-rsi-harness
```

## 2. Run the task

After validation passes, use the matching runner with the bundled read-only `RSI-Harness`.

Local Docker:

```text
$rsi-task-runner
```

Cluster:

```text
$cluster-rsi-task-runner
```

## 3. Submit the trajectory

After the run finishes, commit the completed experiment trajectory generated by the selected runner and push it to this private repository. The task submission is complete only after that push succeeds.
